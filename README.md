# Discord Music Bot

Slash-command YouTube music bot: `discord.js` v14 + `@discordjs/voice` + `yt-dlp`.
Streams audio directly, never downloads files.

## Commands

| Command | What it does |
|---|---|
| `/play <query>` | Joins your voice channel and queues a YouTube video, every video in a playlist, or the best match for search terms |
| `/symus` | Jump to the guild’s control panel, or post it if none is up |
| `/skip` | Skip the current track |
| `/pause` / `/resume` | Pause and resume |
| `/stop` | Clear the queue and leave |
| `/queue` | Current track plus the next 10 queued |
| `/nowplaying` | Current track with elapsed / total time |

A single YouTube Music-styled panel is posted per guild the first time playback
starts, then edited in place for every track and refreshed every 10 seconds. It is
deleted when the session ends. `/symus` links to it rather than posting a rival.

The bot leaves on its own after `IDLE_TIMEOUT_MS` (default 5 minutes) of an empty
queue **or** an empty voice channel.

## Requirements

- Node.js **22+** (the `--env-file` flag is used instead of a `dotenv` dependency)
- No ffmpeg needed. `yt-dlp` hands back Opus-in-WebM and `@discordjs/voice` demuxes
  it directly.
- **Opus passthrough is deliberately given up.** The `/symus` volume control needs
  `inlineVolume`, and scaling audio means decoding Opus to PCM, applying the gain,
  and re-encoding — untranscoded frames cannot be made quieter. `@discordjs/opus`
  (native) is what keeps that re-encode cheap; `opusscript` stays installed as a
  pure-JS fallback and `@discordjs/voice` picks the native binding automatically
  when it loads. Check which one is live with `npm run verify`.
  Drop `inlineVolume` in `src/player.js` to get passthrough back, at the cost of
  the volume and mute buttons.
- The `yt-dlp` binary is fetched by `youtube-dl-exec`'s postinstall. If your npm
  blocks install scripts, run `npm approve-scripts youtube-dl-exec`, then `npm rebuild`.

## 1. Create the Discord application

1. Go to <https://discord.com/developers/applications> → **New Application**.
2. **Bot** tab → **Reset Token** → copy the token. This is `DISCORD_TOKEN`.
3. **General Information** tab → copy **Application ID**. This is `CLIENT_ID`.
4. Still on the **Bot** tab, under *Privileged Gateway Intents*: leave them **all off**.
   This bot only needs the non-privileged `Guilds` and `GuildVoiceStates` intents,
   which need no toggling in the portal.

## 2. Invite the bot

**OAuth2 → URL Generator**:

- Scopes: `bot`, `applications.commands`
- Bot permissions: `View Channel`, `Send Messages`, `Connect`, `Speak`

Or use this URL directly (same permissions, bitfield `3148800`), swapping in your ID:

```
https://discord.com/api/oauth2/authorize?client_id=YOUR_CLIENT_ID&permissions=3148800&scope=bot%20applications.commands
```

The bot also prints this link on startup.

## 3. Run it

```bash
npm install
cp .env.example .env      # Windows: copy .env.example .env
# fill in DISCORD_TOKEN and CLIENT_ID
npm start
```

Slash commands are registered globally on startup — no separate deploy script.
Global commands can take up to an hour to appear the very first time; after that
they update immediately.

```bash
npm test      # offline: URL parsing, time formatting, yt-dlp error mapping
npm run verify  # live: joins a voice channel and confirms audio actually flows
```

`npm run verify` is the one to run when the bot says "Now playing" but you hear
nothing. It prints the voice connection state machine and whether `playbackDuration`
actually advances, which separates "voice handshake failed" from "audio stream died".

## Configuration

|---|---|---|
| `DISCORD_TOKEN` | — | Bot token (required) |
| `CLIENT_ID` | — | Application ID, used for the invite link |
| `IDLE_TIMEOUT_MS` | `300000` | Idle time before leaving the voice channel |

## Notes and troubleshooting

- **Anything that is not a YouTube video/playlist URL is searched**, including a
  truncated or broken paste. Livestreams and zero-duration premieres are skipped
  in the results — they never end, so they would sit in the queue forever without
  ever tripping the idle-leave timer.
- **A `watch?v=…&list=…` link queues the whole playlist.** Autogenerated mixes
  (`list=RD…`) are endless, so those queue the single video only.
- **Age-restricted or region-locked videos** are skipped with a message in chat
  rather than killing the queue. To play age-restricted ones, add
  `'--cookies-from-browser', 'chrome'` to the yt-dlp args in `src/player.js`.
- **Why yt-dlp and not play-dl / ytdl-core?** Both were tried first and both are
  dead against current YouTube — every player client (`TV`, `IOS`, `ANDROID`,
  `WEB_EMBEDDED`, `MWEB`) returns "no playable formats" since YouTube's SABR
  rollout. `yt-dlp` is the only extractor still maintained fast enough to keep up.
- **Playback broke after a YouTube change?** Update the extractor, not the code:
  delete `node_modules/youtube-dl-exec/bin` and `npm rebuild youtube-dl-exec`.
  yt-dlp ships fixes within days.
- **"FFmpeg/avconv not found" after touching the audio pipeline?** Volume needs
  PCM, and `@discordjs/voice` picks the cheapest route to it — from `WebmOpus`
  that is FFmpeg (cost 4.0) rather than its own decoder (4.5). `src/player.js`
  therefore demuxes the WebM itself and passes `StreamType.Opus`, whose graph node
  has no FFmpeg edge at all. Passing `StreamType.WebmOpus` with `inlineVolume`
  brings the crash straight back.
- **"Now playing" but silence?** Almost always `@discordjs/voice` being too old.
  Discord now requires the DAVE end-to-end encryption handshake; anything before
  **0.19.0** connects its websocket, never completes the voice session, and fails
  without an error. Keep `@discordjs/voice` at `^0.19.2` or newer and make sure
  `@snazzah/davey` shows up in `generateDependencyReport()`.
- Audio is never pushed before the connection reaches `Ready` — packets sent
  earlier are silently discarded, which looks identical to "the bot is broken".

## Layout

```
index.js          client, intents, slash-command registration, error handling
src/commands.js   the eight slash commands
src/panel.js      the one-per-guild control panel: embed, buttons, button routing
src/queue.js      guild -> player registry (the queue manager)
src/player.js     URL normalizing/resolving, yt-dlp streaming, playback, idle timeout
test.js           self-check for URL parsing and yt-dlp error mapping
verify.mjs        live smoke test: join a channel, play, assert audio advances
```
